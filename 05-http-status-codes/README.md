# نشاط 5: رموز ردود الـ API

**إعداد:** فياض محمد عبد
**بالاعتماد على محاضرات:** الأستاذ المساعد الدكتور أمير هادي

## الهدف

أن أفهم معنى الرقم الذي يرجعه الخادم مع كل رد، وكيف يتصرف الـ API Client حسب هذا الرقم.

## الفكرة ببساطة

عندما ترسل طلباً إلى الـ API، يرجع الخادم **رقماً من ثلاث خانات** مع الرد. أول خانة تخبرك بنوع النتيجة:

| يبدأ بـ | المعنى | مثال من الحياة |
|---|---|---|
| `2xx` | نجح الطلب | الموظف استلم معاملتك وأنجزها |
| `4xx` | الخطأ من جهة الطالب (أنت) | معاملتك ناقصة أو ليس لديك صلاحية |
| `5xx` | الخطأ من جهة الخادم | الدائرة نفسها فيها عطل |

## أهم الرموز

| الرمز | الاسم | متى يظهر | ماذا يفعل الـ API Client |
|---|---|---|---|
| `200` | OK | الطلب نجح ورجعت البيانات | يعرض البيانات |
| `201` | Created | تمت إضافة سجل جديد | يعرض رسالة "تمت الإضافة" |
| `400` | Bad Request | الطلب مكتوب بشكل خاطئ | يراجع صيغة الطلب |
| `401` | Unauthorized | التوكن غير موجود أو منتهي | يجدد التوكن ثم يعيد الطلب |
| `403` | Forbidden | التوكن صحيح لكن لا توجد صلاحية | يبلغ المستخدم بعدم الصلاحية |
| `404` | Not Found | السجل أو المسار غير موجود | يبلغ أن السجل غير موجود |
| `409` | Conflict | السجل موجود مسبقاً (تكرار) | يمنع الإضافة المكررة |
| `422` | Unprocessable Entity | البيانات ناقصة أو غير صالحة | يعرض الحقل الخاطئ |
| `500` | Internal Server Error | عطل داخل الخادم | يحاول لاحقاً ويبلغ المسؤول |

## أمثلة عملية

الأمثلة على منصة بيانات الموظفين (مثل المشروع 4)، والمسار `/api/employees`.

### 1. جلب قائمة الموظفين بنجاح: `200`

```http
GET /api/employees
Authorization: Bearer abc123
```

```json
200 OK
[
  { "id": 1, "name": "أحمد علي", "grade": "الثالثة" }
]
```

### 2. إضافة موظف جديد: `201`

```http
POST /api/employees
Authorization: Bearer abc123
Content-Type: application/json

{ "name": "سارة حسن", "grade": "الخامسة" }
```

```json
201 Created
{ "id": 2, "name": "سارة حسن", "grade": "الخامسة" }
```

### 3. الطلب بدون توكن أو بتوكن منتهٍ: `401`

```http
GET /api/employees
```

```json
401 Unauthorized
{ "error": "التوكن مفقود أو منتهي الصلاحية" }
```

### 4. طلب موظف غير موجود: `404`

```http
GET /api/employees/99
Authorization: Bearer abc123
```

```json
404 Not Found
{ "error": "لا يوجد موظف بهذا الرقم" }
```

### 5. إرسال بيانات ناقصة: `422`

```http
POST /api/employees
Authorization: Bearer abc123
Content-Type: application/json

{ "name": "" }
```

```json
422 Unprocessable Entity
{ "error": "حقل الاسم مطلوب، وحقل الدرجة الوظيفية مطلوب" }
```

## كيف يتصرف الـ API Client

```text
أرسل الطلب
   │
   ├── 2xx ← نجح: اعرض النتيجة
   ├── 401 ← جدّد التوكن، ثم أعد الطلب مرة واحدة
   ├── 4xx أخرى ← اعرض رسالة الخطأ للمستخدم
   └── 5xx ← حاول لاحقاً وأبلغ المسؤول
```

## أسئلة النشاط

1. أرسلت طلب إضافة موظف ورجع الرقم `201`. ماذا يعني ذلك؟
2. ما الفرق بين `401` و`403`؟
3. حاولت إضافة موظف موجود مسبقاً بنفس الرقم الوظيفي. ما الرمز المتوقع؟
4. لماذا يجدد الـ API Client التوكن عند `401` فقط وليس عند `404`؟
5. رجع الرمز `500`. هل المشكلة في طلبك أم في الخادم؟

<details>
<summary>الإجابات</summary>

1. تمت إضافة الموظف بنجاح وأُنشئ سجل جديد.
2. `401` يعني أن الخادم لا يعرف من أنت (لا يوجد توكن أو انتهى). `403` يعني أنه يعرفك لكنك لا تملك صلاحية هذا الإجراء.
3. `409` Conflict.
4. لأن `401` سببه التوكن، فتجديده يحل المشكلة. أما `404` فسببه أن السجل غير موجود، وتجديد التوكن لن يغير شيئاً.
5. في الخادم، لأن الرموز التي تبدأ بـ `5` تعني خطأ من جهة الخادم.

</details>
